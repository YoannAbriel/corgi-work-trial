# UI-02: actual Corgi dashboard visual language

Base `c778404`, branch `codex/corgi-interface`. Exact source: [manifest](ui-02-source-manifest.json). This supersedes UI-01's visual direction; its technical history remains intact.

## Reference and product decisions

The user authorized observation and navigation in the open customer dashboard at `https://app.corgi.insure/portal/coverage`. Coverage, Endorsements and Claims were viewed through CUA. No form, purchase, endorsement or claim was submitted; no account data was changed or copied into the repository or generation prompts.

The implementation reuses the neutral gray sidebar/workspace, inset workspace frame, compact navigation, bottom account identity, breadcrumb header, orange active state and italic heading emphasis, black actions with a restrained lower shadow, and large bordered white panels. It retains the application's operations-specific destinations and role explanations. No unsupported quote, customer-support or certificate controls were added. Computed reference styles identify F37 Bolton for headings (500, 30/36 px, -0.6 px tracking) and Inter for navigation/body. The application now bundles OFL Inter and DM Sans, including real italics and license notices. DM Sans was chosen after a local visual comparison with Inter and Albert Sans; it is an approximation of F37 Bolton, not an exact match. No F37 web license is confirmed, so no commercial font is redistributed. [Font provenance](ui-02-fonts.json) records sources, subset processing and hashes. Sources checked 2026-09-08: [F37 Bolton](https://f37.com/fonts/f37-bolton), [F37 web license](https://api.f37foundry.com/eula/F37%20Foundry%20EULA%20-%20Web.pdf), [Inter](https://rsms.me/inter/) and [DM Sans source](https://github.com/google/fonts/tree/main/ofl/dmsans).

At the user's request, a screenshot crop containing only the generic heading was uploaded through Chrome to [WhatTheFont](https://www.myfonts.com/pages/whatthefont). The first returned alternatives for “Quotes” included SK Reykjavik Rounded Medium Italic and Armin Soft Semi Bold Italic. They did not establish the actual font; the computed page style remains the direct identification evidence. No account identity or full account screenshot was uploaded.

Selected orange navigation and orange buttons use white text on #ff5c00 to match the user's explicit visual refinement. Buttons use Inter 500 at 16/19.2 px, 8/16 px padding, 12 px radius and a 4 px lower shadow (#626262 black, #cc4a00 orange, #e1e1e1 outline), with the observed hover/pressed colors. Readable supporting links retain the darker accent.

Known accessibility tradeoff: reference color fidelity does not meet all WCAG contrast thresholds. Independent calculations: white/orange 3.096:1, orange heading/gray workspace 2.865:1, white/orange hover 2.551:1, pressed 2.045:1, and white/pressed gray button 4.233:1. No WCAG contrast PASS or full accessibility conformance is claimed. Keyboard focus, native controls and non-color labels remain in place. No additional numeric WCAG requirement was identified in the trial brief.

Original grayscale engraving artwork was generated on the user's Spark with its installed Krea model and existing ComfyUI service. It is used only on home/login/empty-policy views. The operations overview prioritizes task links and role context. [Provenance](ui-02-artwork.json) records the prompt, seed, successful job and final WebP hash. The first generation was inspected and retained; the 45,268-byte image was compressed to WebP. A CSS mask softens its background edge. Earlier UI-01 assets remain as historical work but are no longer displayed by these views.

## Reading path and behavior

Existing page → server `PortalShell` → client `PortalFrame` → global CSS. `PortalShell` still receives the user already fetched by the page and renders the role-dependent navigation/account UI. It passes rendered slots and a section label to `PortalFrame`, not a user/session object or database client. The only new client state is a boolean controlling navigation visibility. Its native button exposes `aria-expanded` and `aria-controls`; the sidebar uses `hidden` when collapsed. Page content and financial actions remain server-owned.

Existing endpoint, form attributes, hidden values, eligibility checks, monetary calculations, queries, provider labels and approval explanations are unchanged. No file under `lib`, `db`, `scripts` or `app/api` changes. No environment variable, migration, provider call or new dependency is introduced. Candidate walkthrough: **NOT REVIEWED WITH YOANN**.

Focus outlines and the previous skip-link/table-scroll controls are preserved. Keyboard Space activation was independently verified. Enter activation remains unverified through CUA: both the native toggle button and a native details summary failed to activate with the tool's Enter/Return attempts, despite focus being confirmed. The reviewer classified this as a tool limitation rather than a demonstrated application defect; no custom key handler was added that could duplicate native activation. Viewport was reset after checks.
